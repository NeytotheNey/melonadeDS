## What's built

- At 1x, affine and tiled extended BGs (`DrawBG_Affine`, 16-bit tilemap `DrawBG_Extended`, no-wrap, ext palettes) are drawn exactly like the CPU in the planes pass, from the latched reference point in the line state block plus nx steps of A and C. They no longer stay CPU as `bgtype`. Bitmap and large BGs, mosaic and rotated sprites still do.
- At 2x and up, a BG with a real rotation or scale is drawn sharp: the planes pass also writes `StackTex` (the pixel's stack without those BGs, plus where each would slot in), and an affine composite samples those BGs per output pixel at `ref + nx*A + floordiv(sx*A + fy*B, S)` and merges them in. Everything else stays once per native pixel. A full-scale planes target was rejected (25 MB at 4x, 100 MB at 8x, and the per-output-pixel stack that stalled the OnePlus).
- After the OnePlus 8x band bug, the affine line constants moved from flat varyings on one quad per line into 3 extra texels per line in `LineStateTex` (11 a line, `PackAffineLine`), the planes pass always writes both targets with fixed draw buffers, and quads go up in one buffer per pass.
- Debug switch `debug.melonade.gpu2daffine` (desktop `--gpu2d-affine N`): `1` draws rotated lines with the plain composite while `StackTex` is still written, `2` also drops `StackTex`. The GPU2D log line ends with `hires=`.
- Desktop: `--at F:scale=N`, `--at F:renderer=gl|compute|soft`, `--at F:shot=FILE.bmp`; the shadow mode is set once, as in the app. `logs/gpu2d-shadow/inc2/desktop.sh` has an `mkrace` scene (real Grand Prix, Figure-8 Circuit, rank swaps at frames 2440–2830). Example: `sh desktop.sh OUT mkrace gl 1 0 3410 256 --at 2000:scale=2 --at 2500:shot=x.bmp`.

## Open

1. **Freeze bug: fixed 11-18, uncommitted, user-confirmed on the Fold.** Mario Kart's bottom-screen icons froze and a garbage band showed in rank swaps at 2x and up. Cause: `StackTex` is draw buffer 1 of `PlanesFB`, and nothing in the compositor set its write mask; the OpenGL 3D renderer leaves it masked after each frame (translucent, edge and fog passes), so `StackTex` went unwritten. The Android `FrameQueue` clear unmasked it for one frame on texture resize (hence "frozen"), and the desktop `Presenter` unmasked it every frame (hence no desktop repro). Not Adreno-only. Fix: `glColorMaski(0/1, all true)` in `RunShadow2DPlanes` before the clear/invalidate; also covers OpenGL→Compute switches. The desktop `Presenter` and `FrameQueue` now only touch buffer 0's mask, so the desktop reproduces the bug without the fix (logs in `logs/gpu2d-shadow/inc2/maskfix/`). `check` only reads back `PlanesTex`, so it can't catch a broken `StackTex`; worth adding. Fold test APKs: `5a1c158f` (fix) and `2c1b5fbb` (fix + per-frame clear), both good; the clear was dropped. Remote by-eye tests: Debug switches `gpu2d=all gpu2daffine=0`.
2. **8x cost on the OnePlus, re-measured 11-18 with the mask fix** (APK `b8f9bbed`, `perf_logs/2026-11-18-shadow2d-maskfix/`, one 30 s pass each, OpenGL 8x Mario Kart demo race): `0` 59.7/59.7 fps, render 1.68 ms; `all` 54.8 emulated / 46.0 presented, render 16.3 ms mean (17.0 median), 1% low 26.6; `gpu2daffine 1` 59.1/58.4, 2.86 ms mean (1.64 median, a 61 ms hitch, not repeated). So cheaper than `a5ff5c9f` (28 ms → 16 ms) but still ~14 presented fps down at 8x. Pixel 8 has no cost at 8x (60.2 fps and ~2.8 ms in all three). OnePlus 8x: 0 black rows in 76 shots, bottom screen animating, no garbage. `check` 0 mismatches in all 12 runs (OnePlus + Pixel, OpenGL + Compute, 1x/4x/8x).
