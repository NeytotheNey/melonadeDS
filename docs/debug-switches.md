# Debug switches (debug builds only)

The full, current list with defaults is the comment block in `app/src/main/cpp/debug/DebugProperties.h`. This file explains the older ones. Compute switches are explained in `HANDOFF-compute.md`, and the GPU discovery ones (`gltimers`, `scenestats`, `hash3d`, `gltrans`, ...) in `docs/plan-gpu-discovery.md`.

Set with `adb shell setprop debug.melonade.<name> <value>` before starting a game; clear with `adb shell "setprop debug.melonade.<name> ''"`. Without adb, type `name=value` pairs into the switch field in Settings → Performance → Diagnostics; they apply at the next game start. The debug log's `Debug switches` line shows what took.

- `threaded2d` 1/0: overrides the threaded 2D setting.
- `hash2d` 1: logs `HASH2D frame=<n> top=<hex> bottom=<hex>` (tag `melonade`) each frame, an FNV-1a over both 2D back buffers. Proves a 2D change is output-identical. At 60 FPS the core's log limit (50 lines a second per call site) drops about 15% of the lines.
- `cpusemu` / `cpus2d`: comma lists of CPU ids to pin the emulator / 2D thread.
- `defercap` 0: turns off deferred display capture (OpenGL). `earlyflush` 0: turns off the early GPU flush.
- `capreads` 1: logs how often games read display capture results and why held capture lines get drawn early (`CAPREADS` and `CAPFLUSH` once a second, sampled `CAPTRACE` and `CAPDIRTY` per frame); see `GPU_CaptureReads.h`.
- `bnohold` (OpenGL/compute): `1`, the default in every build since 11-16, draws engine B's part of held capture lines right away and holds only engine A's; `0` is the old path.
- `hirescap`: `0` off, `1` on (overrides "Upscaled display capture"), `log` adds a once-a-second `HIRESCAP` line, `check` also runs the pass at 1x and compares against native VRAM every 30 passes. See `docs/hires-capture.md`.
- `halfcam` (OpenGL/compute): frame interpolation for 30 FPS games. `4` is the one to use; `1` camera only, `2` adds characters, `3` adds batch logging, `5` a per-pair trace. See `docs/shelved/frame-interpolation.md`. The "Debug switches:" line shows the property itself (`-1` when unset); the Smooth 30 FPS setting is the `frame_pacing_smooth_30fps` config line.
- `gpu2dstats` 1: once-a-second `GPU2DSTATS eng=A|B` line counting BG types, sprite features and mid-frame VRAM/palette/OAM changes; fields in `GPU_2DStats.h`.
- `gpu2d` (OpenGL/compute): the GPU 2D shadow renderer. `0` off, `1` only lines that gain something, `all` every eligible line, `check` all plus a 1x readback compared with CPU 2D every 30 frames, `log` adds a once-a-second `GPU2D` line. `gpu2dwide` 1: every layer draws past the screen edge (test only). See `docs/plan-gpu-2d-shadow.md`.
- `widedrops` 1: once-a-second `WIDEDROPS` line on polygons dropped because polygon or vertex RAM was full. Fields: `width` the view width, `widelist` 1 while `widepolys`'s wide list is on, `scenes` polygon RAM swaps that second, `dropscenes` those that dropped any, `drops` all polygons dropped, split into `native` (the DS would drop them too), `wing` (only the wide view kept them) and `nativefit` (the native view had room, so the wide view cost them; 0 at 256, and should stay 0 with the wide list), `maxscene` the most drops in one scene, `peaknpoly`/`peaknvert` the native view's fullest polygon and vertex RAM at a swap (of 2048/6144), `peakpoly`/`peakvert` what was stored (of 2048/6144, or 4096/12288 with the wide list), `peakwing` the most polygons in the wide list's wing budget (of 2048). See `docs/plan-widemelon.md`. Desktop: `--widedrops`.
- `widey` (WideMelon camera stage 2, `docs/plan-widemelon.md`), default 1, `0` for A/Bs: with 0 the core renders no margin rows above and below the top screen (M = 0), so a zoomed-out camera letterboxes as in stage 1.
- `widepolys` (WideMelon, `docs/plan-widemelon-polylist.md`), default 1 since 11-14, `0` for A/Bs: with the view wider than 256, the game sees the native view's polygon and vertex RAM counts (registers 0x04000604/606) and DISP3DCNT bit 13, and the scene is kept in a list twice the DS's size (4096 polygons / 12288 vertices a bank), 2048/6144 of it reserved for polygons only the wings show. A polygon the native view keeps is dropped only where the DS drops it (and then from the wings too); a wing-only one stops once the wing budget is full or the native counts couldn't take one its size, so an object can't lose its middle half and keep its wing half. Latched with the view width at the next polygon RAM swap. Savestates keep GP3D's format and add a `GP3W` section only while it's on (old builds skip it; a state saved with a bank over 2048 shows one garbage frame there). Compute builds its programs for 4096 polygons on wide targets with it on (12-bit polygon indices in the work descriptors). `0` is the code before it exactly. A/B it with `widedrops=1`. Desktop: `--set WidePolys=1`; swi-harness: `--wide-check W --wide-polys 1` (bit 13, the native counts and the count reads then have to match), `WIDEPOLYS=1` for `wide_check.sh`.
- `filter2d` (OpenGL/compute): `0` off, `1` on (overrides "Smooth 2D edges"), `2` only the 2x MMPX pass, `3` all passes with identity output, which must match off. See `docs/plan-gpu-2d.md`. The `FILTER2D` line's `rows` is `filter2drows`, `partial` how many of the frames that ran redrew only some rows, `passrows` the rows each pass drew on average (key / first MMPX pass / second, of 384 / 768 / 1536).
- `filter2drows` (OpenGL and compute, experiment K3 in `docs/plan-gpu-discovery.md`), default 1 in every build since 11-11 (`0` redraws the whole map as before): with filtered 2D, a frame whose keys changed on only some lines redraws only the map rows they can reach (each MMPX pass reads 3 rows up and down, so the changed lines widen by 3 source rows per pass), scissored, without invalidating the targets. `2` checks: every 30th partial redraw, all targets are read back, drawn again in full and compared (`rowchecks` and `rowmismatches` on the `FILTER2D` line, with a `FILTER2D rowcheck mismatch` line for the first few texels). Desktop: `--set Filter2DRows=N` (`--set Filter2DLogging=1` for the line, `--filter2d-mode N` for the other `filter2d` modes).
- `vertexid` 1: once-a-second `VERTEXID sec` line on vertex identity between 3D scenes; 2 adds `VERTEXID scene`. Fields in `GPU3D_VertexId.h`.
- `blitflush` 0 (compute): in frames that hold capture lines, no GPU flush right after the line-192 Blit.
- `lateblit` 0: with threaded 2D on OpenGL/compute, the frame-end 2D barrier and the Blit stay at line 192 instead of just before the line-215 3D render.
- `capspin` 0 (compute): the capture readback sleeps in its map instead of first polling a fence for up to 6000 µs; another value sets that limit (max 20000).
- `gltrans` (OpenGL, experiment T1 in `docs/plan-gpu-discovery.md`), a sum of bits, default 3 in every build (`0` draws as before): `1` skips pass 3's opaque redraw of need-opaque polygons after the clear0 pass, `2` skips need-opaque draws their texture can't pass (CPU scan), `4` (T1c) drops the clear0 pass when the clear alpha is 0 and the GPU has `GL_EXT_shader_framebuffer_fetch`: pass 3's translucent shader reads the color target and doesn't blend over alpha 0. Without the extension (desktop, maybe Mali) `4` changes nothing. A/B it as `gltrans=3` against `7` with `hash3d=1`; with `scenestats=1` the `GLTRANS` line's `fetch_frames` counts the frames drawn that way (out of `clear0_frames`).
- `gledgeskip` (OpenGL, experiment E2 in `docs/plan-gpu-discovery.md`), default 1 in every build since 11-12 (`0` draws as before): `1` leaves out the final pass's edge-marking draw, and the whole final pass with its depth/stencil detach when fog is off too, in frames where nothing set the edge flag (`gledgemark=0`, or no polygon drawn opaque), where the edge shader blends `(0, 0, 0, 0)` everywhere. A/B it with `hash3d=1` and `gltimers=1` (the `edge` part goes away); A/B `gledgeskip=0 glclear=0` against the defaults. Desktop: `--set GLEdgeSkip=0`.
- `gledgemark` (OpenGL, experiment E1 in `docs/plan-gpu-discovery.md`), default 1 since 11-15: edge marking (DISP3DCNT bit 5), which GL never drew before E1. The app's Video setting "Edge marking" (`video_edge_marking`, on by default, hidden for software) sets it to 1 or 0 at every renderer update; this switch, when set, overrides the setting (debug builds). `0` no edge flags, as before E1, and Compute's final pass leaves its edge marking out too (that's what the setting's off does on Compute). `1` opaque fragments set the edge flag when a neighbor one DS pixel away is outside their polygon's outline (inner fan diagonals don't count), through program builds used only in edge-marking frames and a per-polygon outline texture. `2` every opaque fragment has the flag (same program builds, no outline work; marks more where a different-ID polygon is just in front inside an outline). Both use a one-DS-pixel neighbor offset and the clear plane past the target's edges, like software, and compare depth-equal (decal) polygons at their own depth: attr G also says whether the opaque draw was moved nearer by the depth-equal margin (`equaldepth`), and the edge pass adds that back. Known gaps: a depth-writing translucent pixel keeps the G of the opaque pixel under it, so its depth is unbiased by that pixel's bit, not its own; concave polygons (rare on the DS) over-flag along a reflex edge's extended line inside the polygon. Desktop: `--set GLEdgeMark=N` (0-2).
- `gledgefast` (OpenGL, E1 speedups in `docs/plan-gpu-discovery.md`), a sum of bits, default 2 since 11-15 (`0` for A/Bs), exact against `gledgefast=0` with `gledgemark=1` (hash3d) on the desktop, the OnePlus 7 Pro and the Pixel 8. `1` the edge pass discards pixels without the edge flag right after the attr fetch (no depth fetch, no blend) and is scissored to the box of the polygons drawn opaque; no gain measured on Adreno or Mali (11-15), so it's off. A stencil test isn't possible there: the depth/stencil texture is detached for the pass, since the shader samples its depth, and the opaque shader can't write a per-fragment stencil value anyway. `2` with `gledgemark=1`, polygons with up to 4 edges get them as 3 flat `highp vec4` varyings (12 floats a vertex, in a buffer only uploaded in those frames) instead of RGBA32F texel fetches; more edges still use the texture. OnePlus opaque pass -11%, Pixel 8 neutral at 8x and -9% at 16x. If its programs don't build, it logs once and draws from the texture for the renderer's life. `4` (debug builds) makes those programs fail on purpose, to test that. Caveat: GLSL ES doesn't promise the same float results for the same expression in two different programs, so `2` against `0` could differ by a stray pixel on a diagonal outline on some driver; none seen so far. A/B with `gltimers=1` (`edge` and `opaque`). Desktop: `--set GLEdgeFast=N`.
- `glclear` (OpenGL, experiment D1 in `docs/plan-gpu-discovery.md`), a sum of bits, default 3 in every build since 11-12 (`0` draws as before): `1` the plain clear (not the clear bitmap, DISP3DCNT bit 14) is a `glClearBuffer` per target (color, attr, depth/stencil with T1c's 0xBF stencil kept) instead of the full-screen quad, with the same values; `2` invalidates the attr and depth/stencil targets after the frame (`glInvalidateFramebuffer`), since only the color target is read after it. A/B `gledgeskip=0 glclear=0` against the defaults with `hash3d=1`; `gltimers=1`'s `clear` part shows the cost. Desktop: `--set GLClearFast=N`.
- `glnodiscard` (OpenGL, experiment R1 steps 1 and 2 in `docs/plan-gpu-discovery.md`), a sum of bits, default 3 since 11-13 (1 before step 2), in every build (`0` draws as before, for A/Bs): `1` draws the opaque pass's polygons that can't discard a fragment with a second Z-buffer program built without `discard` (`RenderShader[4]`, opaque only, built the first frame that wants it), so the GPU can test depth before shading. A polygon qualifies when it's opaque (not translucent, so no need-opaque draws), not a shadow or mask, has polygon alpha 31, and is untextured (or texturing is off), decal, or uses a palette texture (I2/I4/I8) without a transparent color 0. `2` (step 2) adds the textures that need a scan: direct color with no alpha-bit-0 texel, 4x4 with no transparent texel (index 3 in block modes 0 and 1, the mode read from the slot 1 index data the shader reads), and palettes with color 0 transparent but no index-0 texel, so `3` is both steps. The scan covers every texel of the texture's width x height (any wrap or flip stays inside it); a texture reaching past the 512 KB of texture VRAM (or a 4x4 one spanning two slots) doesn't qualify. Results are kept across frames and dropped when texture VRAM changes in a 512-byte chunk they read (the same dirty chunks the TexMem upload uses), on reset and on a savestate load. `4` is a check that drops them every frame instead: `glnodiscard=7` against `3` must hash the same. Any nonzero value turns step 1 on, so `2` acts as `3`. Z-buffer frames only: W-buffer frames write `gl_FragDepth`, which blocks early-Z anyway. The polygons get a key bit, so a batch splits where the program changes; with `scenestats=1` the `GLOPAQUE` line's `nd`/`nd_area` count them per Z frame, `draws` against `draws_base` the extra draw calls and `prog_switches` the added `glUseProgram` calls; with bit 1 on, `nd` takes `texop` too, `textures`/`bytes` count the scans the cache didn't have and `nd_scan_us` is bit 1's CPU time per frame. Exact: A/B it with `hash3d=1`. Desktop: `--set GLNoDiscard=0` to turn it off, `--set GLNoDiscard=1` for step 1 only.
- `gltexprobe` (OpenGL), a measurement probe for experiment T2 in `docs/plan-gpu-discovery.md` that **renders wrong on purpose**, default 0 (draws as before): it bounds how much GPU time a decoded texture cache could save. `1` makes the render programs' texture lookup (nearest and linear) one `texelFetch` from the already bound palette texture at the texcoord's texel, with alpha 1, instead of wrapping and decoding texture VRAM; `2` returns a constant 1.0 with no fetch, so `0` vs `1` is the decode and `1` vs `2` the fetch. Two more measurement modes: `3` is `1` after the old path's `TexcoordWrap` on both axes (`1` vs `3` is the wrap), and `4` is the wrap followed by two dependent fetches like T2's (a TexMem byte at I8's address from the wrapped texel, then the palette entry it indexes, alpha 1, no kind branches or alpha decode). Alpha 1 means texture cutouts and translucent texels come out opaque, while the polygon's own alpha still picks the pass. Passes, draws and program keys stay the same; the render programs are rebuilt the first frame the switch differs from what they were built with (a `GLTEXPROBE` log line). Never for hash3d or image checks.
- `gltexcache` (OpenGL, experiment T2 steps 1 to 4b in `docs/plan-t2-texcache.md`), a sum of bits, default 449 since 11-14 in every build (steps 2, 3 and 4 with the record path left out of the main programs; 1 was the default from 11-13 and is the A/B baseline against it; `0` draws as before and makes no GL objects): `1` (any nonzero value) decodes each texture once on the CPU into texel records in a heap texture (RGBA8UI 1024 x 4096, 16 MB, plus a 96 KB copy of the palette 256 entries a row) and the render programs read the record instead of decoding texture VRAM per fragment. The records hold the integers today's fetches compute (palette coordinates, alpha, a kind), so the shader runs the same float math on the same palette words and the image should stay the same: A/B it with `hash3d=1`. Textures are kept until texture VRAM under them changes (the same 512-byte dirty chunks the TexMem upload uses), then hashed again at their next use (XXH3) and decoded again only when their bytes changed; palette changes cost nothing. A polygon takes the old path when its texture reads past texture VRAM or the palette, the frame's decode budget (256K texels) is spent, the heap is full, or the texture changed in 3 of the last 8 frames it was used in (old path for 120 frames). `2` is a check that decodes every used texture again every frame (no reuse, no budget), `4` a tiny budget (4K texels a frame) and heap (128K texels) so both paths mix within a frame, `8` no budget and no volatile rule. Step 2 (the design's section 10) is what `1` runs: the programs most polygons draw with (served, untextured, texturing off) are built without the old decode path, and the polygons the heap doesn't serve get a render key bit (0x40000, so batches split only where it changes) and draw with twins of each program in use (Z, W, framebuffer fetch, no-discard, and the SCENEFRAGS counting builds) that keep the old path, made the first frame such a polygon shows up. If a twin doesn't build, a `GLTEXCACHE` warning and the cache turns off from that frame on (the frame is drawn as with `0`) until the value changes; `32` (debug builds only) makes the twins fail on purpose to test that. `16` runs step 1 instead, one program with both paths, for A/Bs (`17` vs `1`). `64` is step 3: the heap lookup's per-polygon wrap constants (mask and mirror per axis) are made in the vertex shader into one more flat varying (`mediump ivec4`), and the fragment shader wraps without branches, the same texels as `TexcoordWrap` for every texcoord; the old decode path and the twins' old fetches keep `TexcoordWrap`. `65` is step 2 with it, `81` step 1 with it, and it combines with `2`, `4` and `8` (`69` tiny budget, mixed paths). `128` is step 4, off by default (plan section 13): I2/I4/I8/A3I5/A5I3 textures also get a color plane (an RGB5_A1 texture the heap's size, 8 MB, each texel's palette word resolved when it's decoded) and the shader reads that instead of the record and its dependent palette fetch (A3I5/A5I3 still read the record at the same address for their alpha); 4x4 and direct keep the record path. Since step 4b (11-14) palette changes are tracked: an entry whose palette words changed re-resolves its plane at next use, one whose palette changed in 3 of the last 8 frames used reads its records for 120 frames, and one over the decode budget reads its records that frame, so `193` (steps 2, 3 and 4) vs `65`, or `129` vs `1`, is exact with animated palettes too (check it with `hash3d=1`). `256` (with `128` and step 2, debug, measurement) builds the cache-only programs without the record path at all; served 4x4 and direct textures then draw with the twins (`449` = 256 + 193, `385` = 256 + 129; ignored without 128 or with 16). `gltexprobe` wins while it's nonzero. The render programs are rebuilt the first frame the switch turns on or off (a `GLTEXCACHE` log line); any change of the value starts the heap over. With `scenestats=1` a `GLTEXCACHE` line once a second: textured polygons and area, the share the heap served (`cover`, `cover_area`), how (`hit`, `kept`, `decoded`, `redecoded`), why the rest fell back (`range`, `palette`, `volatile`, `budget`, `full`), served area per format, heap entries and use, decoded texels, uploads and KB, the CPU µs of decoding, uploading, hashing and the whole pass (`assign_us`), and step 2's `s2_full` (polygons drawn with the twins), `s2_draws` against `s2_draws_base` (the opaque and translucent batches with and without its key bit) and `s2_switches` (program switches it adds), and step 4's `color` (served polygons and area that read the color plane), `color_full` (served ones `256` sent to the twins), `color_vol` and `color_budget` (served ones that read records because their palette was volatile or the budget was spent), `pal_rehash` and `pal_kept` (palette rehashes and how many found no change), `resolves` and `resolve_texels` (plane-only re-resolves), `pal_volatiles` and `pal_vol_entries` (entries that went palette-volatile, and the average count); `hash_kb` and `hash_us` include the palette rehashes. `GLOPAQUE`'s `draws` leave that bit out, so they compare across `gltexcache` values. Desktop: `--set GLTexCache=N`; `--at F:reset`, `--at F:state` and `--at F:GLTexCache=N` reset, reload the `--state` or change a switch before frame F.
- `compclear` (OpenGL and compute, experiment K2a in `docs/plan-gpu-discovery.md`), default 0 (draws as before): the compositor's main draw starts without the output's old contents, so a tiled GPU needn't load every tile first. `1` clears the whole output to 0 right before that draw, `2` invalidates it (`glInvalidateFramebuffer`) and clears only the padding rows between the screens. The draw covers every other pixel, so both should leave the output the same. Desktop: `--set CompClear=N`.
- `comp1x` (OpenGL and compute, experiment K2c in `docs/plan-gpu-discovery.md`), default 1 in every build since 11-11 (`0` draws as before): a screen with nothing the scale adds (no 3D, no 3D or held wings, no hi-res capture lines) is composited at 1x into the first width x 192 texels of its half of the frame, and the screen shader shows it nearest-upscaled from there. Only while every surface uses the "None" filter with no deband and no Lua tilt-shift (a frame with a screen at 1x that meets another filter, a pre-pass or a tilt-shift, such as one already queued when the filter changes or a paused one, is first expanded into the full frame, so it looks the same), and not in frames with filtered 2D or GPU 2D (`gpu2d`) lines. `1` in a wide view only, where it's pixel-exact; `2` the 256 view too, whose mediump full draw rounds some sub-pixels into the next DS pixel on fp16 GPUs (the RTX 5090 too), so the image changes there (the 1x one is the exact one); `3` checks: the full draw as usual, and every 30 frames the plain screens at 1x into a target of their own, read back and compared, with a `COMP1X mismatch` line for the first few differing pixels. With `scenestats` or `gltimers` on (always in `3`), a `COMP1X` line once a second: frames, how many had only the top / only the bottom / both screens at 1x (in `3`: plain), and why the others couldn't (`front` the frontend, `scale` 1x, `view` the 256 view in mode 1, `nolines`, `filter`, `shadow`), plus the checks. Desktop: `--set Comp1x=N` (`--linear` keeps it off, `--set SceneStats=1` for the line). With filtered 2D (K3), a plain screen is drawn with the filter's program at the filter map's scale instead of 1x and upscaled by the rest (4x at 8x, 12x and 16x; 2x at 4x and 6x with `filter2d=2`), in the 256 view too in `1`, since that program doesn't read its mediump varying there; at scales the map doesn't divide, at the map's own scale, and in `filter2d=3`'s 256 view, both screens are drawn in full (`filter`). The `COMP1X` line's `filtered` counts the frames whose screens were filtered that way, and `3` checks those too.
- `shadowfix` 0 (OpenGL): clear the shadow mask over the whole screen for every mask, instead of per line like software. `maskdepth` 0: depth-equal shadow masks and shadows use plain GL_LESS/GL_LEQUAL, without the DS margin. `equaldepth` 0: the same for all other depth-equal polygons. `shadowlog` 1 (or a frame count): for the first 300 frames, `SHADOWSTATS` and `SHADOWLOG` lines listing masks and shadows.
- `debandfold` (frontend, `docs/plan-deband-outcap.md` part A), default 1 since 11-15 (`0` is the old deband pre-pass): `1` debands inside the Sharp or Linear screen shader, once per drawn screen pixel, instead of the pre-pass over every frame texel, while no Lua tilt-shift runs and the screens draw fewer pixels than the frame has texels; every other filter, and every other case, keeps the pre-pass. Read by the Kotlin renderer (Debug switches setting, then setprop) at each game start, so it is not in the perf log's active switches; the `DEBANDFOLD` logcat line (tag of the `OUTCAP` line) says which one each surface uses whenever that changes.
- `outcap` (OpenGL and compute, experiment K4 in `docs/plan-k4-output-cap.md`), a sum of bits, default 1 in every build (`0` keeps the output at the internal scale): `1` caps the compositor's output at the scale the screens are shown at. Since `docs/plan-deband-outcap.md` part B, while deband is on (any surface's screen filter; an in-game toggle counts, applied with the need's 30-frame hold) the cap also takes output scales that don't divide the internal one, above half of it, so 8x gives 6x for a need of 6 (12x gives 7x-11x, 16x 9x-15x); with deband off it stays at a whole fraction of the internal scale (8x stays 8x for a 6x screen), since the smaller frame only pays for itself through deband's cost. Each output pixel then weighs the 2 or 3 3D pixels a side under it by how much of each it covers, an area resample of the full-scale frame (exact with `outcap3d=0`). Bit `2` (`outcap=3`) takes those scales whatever deband does, bit `4` (`outcap=5`) never does, which is the output from before part B; `2` wins if both are set. The `OUTCAP` line says `ratio 4/3` for 8x at 6x and ends with why such ratios are allowed or not (`ratios any (deband on)`, `ratios whole (deband off)`, `ratios any (forced, outcap bit 2)`, `ratios whole (forced, outcap bit 4)`); the `melonade-debug` lines show the deband flag the frontend sends and when it's accepted. `outcapneed=N` overrides the screens' need, as before.
- `ldmfast` (ARM64 JIT with fast memory), default 1, `0` for A/Bs: multi-register loads (ARM `LDM`, Thumb `POP` and `LDMIA`) read guest memory straight through fastmem with `LDR`/`LDP`, like single loads and like block stores already did, instead of calling `SlowBlockTransfer9/7` for every word. A load that hits memory fastmem can't map faults once and that instruction is patched to the old slow call. It adds the same cycles either way (they are fixed when the block compiles), so emulation timing doesn't change. `0` is the old store-only fast path. Set at game start before anything compiles; changing it later throws the compiled blocks away. User-mode `LDM ^` always takes the slow path. No effect on x64, which always had loads on the fast path. The `Debug switches:` line has `ldmfast=`.
- `ldmstats` 1 (JIT): about every 5 s, two lines (tag `melonade`, or `melonade-core` while the debug log is on) on the slow multi-register loads and stores that go through `SlowBlockTransfer9/7`, counted since the last pair. `LDMSTATS run` has, per stream (`9r` `9w` `7r` `7w`: CPU, read or write), `calls/words`, then on ARM64 `nofast` (calls from transfers compiled without a fast path) and `patched` (from fast paths the fault handler turned into a slow call), `cross` (transfers ending in another region) and `calls/words` per region of the start address (`main` `dtcm` `itcm` `swram` `wram7` `nwram` `io` `wifi` `vlcdc` `vabg` `vbbg` `vaobj` `vbobj` `vram7` `pal` `oam` `bios` `gba` `other`, only the ones hit). `LDMSTATS jit` counts the block transfers the ARM64 JIT compiled, by outcome (`fast`, `fastcond` and `fastthumb` for a fast path taken although the predicted region isn't fastmem compatible, `single`, or the reason for none: `nofastmem`, `ldmfast`, `user`, `region`), `<stream>.rgn` the predicted regions of the `region` ones, and `patch` the fast paths rewritten to the slow call (`single` for single loads and stores). Counting only, no effect on emulation; x64 gets the `run` line without `nofast`/`patched` and an empty `jit` line. Fields in `ARMJIT_LdmStats.h`. The `Debug switches:` line has `ldmstats=`.
- `ldmdirect` (JIT), default 1, `0` for A/Bs: a multi-register load or store that goes through `SlowBlockTransfer9/7` is done straight in host memory when all its words fall in one plain region: ITCM, DTCM or main RAM at `0x02xxxxxx` for the ARM9, main RAM or ARM7 WRAM (`0x038xxxxx`-`0x03Fxxxxx`, DS only) for the ARM7. Otherwise, and for a transfer that leaves its region or wraps around inside it, every word takes the full bus read or write as before. Same values and the same JIT code invalidation per word as the old loop, and no cycles change (the slow path adds none), so the image should hash the same. It's read on every transfer, so it can change at any time without recompiling. `ldmstats` counts these calls either way. The `Debug switches:` line has `ldmdirect=`.
- `jitdispatch` 1 (ARM64 JIT), default 0 for now: a block's exit does the `Execute` loop's work between two blocks itself, in a stub in the generated code (`Compiler::Gen_DispatchStubs`): add the block's cycles to the timestamp, check the frame's target, find the next block in the CPU's lookup window and jump straight to it. When `StopExecution` is set (an IRQ, a halt or an idle loop), the target is reached, the PC is outside the window or no block is in the table, it goes back through `ARM_Ret` to the loop as before. It does the same checks in the same order, so emulation and timing should be identical (`tools/jitverify --jitdispatch 0|1`). It changes compiled code, so it's read at game start and a change needs a game restart. No effect on x64. The `Debug switches:` line has `jitdispatch=`.
