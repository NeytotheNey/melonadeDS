# Debug switches (debug builds only)

The full, current list with defaults is the comment block in `app/src/main/cpp/debug/DebugProperties.h`; this file adds the A/B recipes and gotchas. Compute switches are explained in `docs/plan-compute-efficiency.md` (the Mali diagnostics `computecheck`, `computebin`, `computecalc`, `computeflat`, `computessbo` in `docs/compute-on-mali.md`), and the GPU discovery ones (`gltimers`, `scenestats`, `hash3d`, ...) in `docs/plan-gpu-discovery.md`.

Set with `adb shell setprop debug.melonade.<name> <value>` before starting a game; clear with `adb shell "setprop debug.melonade.<name> ''"`. Without adb, type `name=value` pairs into the switch field in Settings → Performance → Diagnostics; they apply at the next game start. The debug log's `Debug switches` line shows what took. Desktop: most core switches are `--set Name=N` (`--list-sets` lists them).

## Checks and logging

- `hash2d` 1: logs `HASH2D frame=<n> top=<hex> bottom=<hex>` (tag `melonade`) each frame, an FNV-1a over both 2D back buffers. Proves a 2D change is output-identical. At 60 FPS the core's log limit (50 lines a second per call site) drops about 15% of the lines.
- `hash3d` 1: logs `HASH3D frame=<n> hash=<hex>` per frame, a hash of the 3D image at native resolution; the check for every "exact" GL switch below. Costs a blit and a 192 KB readback a frame on the GPU renderers.
- `gltimers` 1 (OpenGL): a `GLTIME` line once a second with the GPU µs of each pass; `2` times them on the CPU between `glFinish` calls instead (slow, compare its `share=` list). `bad=` counts the sets dropped because a pass read over a second (the Adreno 640 can return a negative time, read as nearly 2^64, when the GPU is far behind).
- `scenestats` 1: a `SCENESTATS` line once a second on the scenes rendered (any renderer); on OpenGL also the `GLTRANS`, `GLOPAQUE` and `GLTEXCACHE` lines. `2` adds per-fragment counts (`SCENEFRAGS`), which slows it down.
- `capreads` 1: logs how often games read display capture results and why held capture lines get drawn early (`CAPREADS` and `CAPFLUSH` once a second, sampled `CAPTRACE` and `CAPDIRTY` per frame); see `GPU_CaptureReads.h`.
- `gpu2dstats` 1: once-a-second `GPU2DSTATS eng=A|B` line counting BG types, sprite features and mid-frame VRAM/palette/OAM changes; fields in `GPU_2DStats.h`.
- `vertexid` 1: once-a-second `VERTEXID sec` line on vertex identity between 3D scenes; 2 adds `VERTEXID scene`. Fields in `GPU3D_VertexId.h`.
- `widedrops` 1: once-a-second `WIDEDROPS` line on polygons dropped because polygon or vertex RAM was full, split into `native` (the DS would drop them too), `wing` (only the wide view kept them) and `nativefit` (the native view had room, so the wide view cost them; should stay 0 with `widepolys`), plus peak polygon and vertex RAM use. See `docs/plan-widemelon.md`. Desktop: `--widedrops`.
- `shadowlog` 1 (or a frame count): for the first 300 frames, `SHADOWSTATS` and `SHADOWLOG` lines listing masks and shadows.
- `ldmstats` 1 (JIT): about every 5 s, `LDMSTATS run` (slow multi-register loads and stores through `SlowBlockTransfer9/7`, by CPU, direction and region) and `LDMSTATS jit` (how the ARM64 JIT compiled block transfers and why some got no fast path). Counting only. Fields in `ARMJIT_LdmStats.h`.

## Threads and capture

- `threaded2d` 1/0: overrides the threaded 2D setting.
- `cpusemu` / `cpus2d`: comma lists of CPU ids to pin the emulator / 2D thread.
- `defercap` 0: turns off deferred display capture (OpenGL). `earlyflush` 0: turns off the early GPU flush.
- `bnohold` (OpenGL/compute): `1`, the default in every build since 11-16, draws engine B's part of held capture lines right away and holds only engine A's; `0` is the old path.
- `blitafterread` (OpenGL/compute), default 1 since 11-16, `0` is the old path: in frames that hold capture lines, the Blit moves from line 192 to right after the line-215 3D render, and the next frame's capture readback to between the two.
- `heldworker` (threaded 2D, OpenGL/compute), a sum of bits, default `63` since 11-16 (`0` is the old path): moves the drawing of held capture lines off the emulator thread onto the 2D thread. `1` (needs `bnohold`) queues engine B's part of each held line at its HBlank. `2` (needs `blitafterread`) queues the held lines at line 192, so they and display capture run on the 2D thread during lines 192-215; the emulator thread waits for them at line 215 or at anything that touches LCDC VRAM before then. With `2`: `4` waits at the Blit after the line-215 render instead, `8` doesn't wait at a POWCNT write or an LCDC read of a bank their capture doesn't write. `16` (with `1`) hands the engine B parts over 16 lines at a time so the 2D thread sleeps instead of spinning. `32` (with `2`) backs off by itself for 120 frames when the emulator thread had to wait for the lines before the Blit in 2 of the last 8 frames (a game reading its own capture in VBlank, like Golden Sun Dark Dawn). The output must match `0` byte for byte (`hash2d`). `2` does nothing while `capreads` is on. `63` doesn't regress on the Fold, OnePlus or Pixel (PERF-NOTES "Held 2D lines on the 2D thread"). Desktop: `--set HeldTo2DThread=N`.
- `blitflush` 0 (compute): in frames that hold capture lines, no GPU flush right after the line-192 Blit.
- `lateblit` 0: with threaded 2D on OpenGL/compute, the frame-end 2D barrier and the Blit stay at line 192 instead of just before the line-215 3D render.
- `capspin` 0 (compute): the capture readback sleeps in its map instead of first polling a fence for up to 6000 µs; another value sets that limit (max 20000).
- `glpace` (OpenGL), default 1, `0` is the old path: OpenGL's version of Compute's `computepace 1`. A fence goes in after each Blit's compositor draws, and the next Blit holds the emulator thread (100 ms at most) while two frames are unfinished, so a GPU that overruns drops fps a little instead of the driver queue piling up delay until presented fps collapses (the OnePlus 7 Pro's GPU 2D shadow stall). While the GPU keeps up it never waits, and a frame that maps a capture readback has already waited for more. Setting it logs a `GLPACE` line once a second: `waits`, `wait_ms`, `maxwait_ms`, `timeouts`, `stale` (fences over half a second old, dropped unsignaled) and `maxpending`. Kept on by default after the 11-17 A/B on all three phones (free while the GPU keeps up; see `PERF-NOTES.md`, "OpenGL render pacing"). Desktop: `--set GLPace=N`, `--set GLPaceLog=1`.
- `hirescap`: `0` off, `1` on (overrides "Upscaled display capture"), `log` adds a once-a-second `HIRESCAP` line, `check` also runs the pass at 1x and compares against native VRAM every 30 passes. See `docs/hires-capture.md`.

## 2D

- `gpu2d` (OpenGL/compute): the GPU 2D shadow renderer. `0` off, `1` only lines that gain something, `all` every eligible line, `check` all plus a 1x readback compared with CPU 2D every 30 frames, `log` adds a once-a-second `GPU2D` line. Any of these, `0` too, replaces the "Sharper rotated 2D" setting (mode `1`) for that game; unset, the setting decides. `gpu2dwide` 1: every layer draws past the screen edge (test only). See `docs/plan-gpu-2d-shadow.md`. Desktop: `--gpu2d N` (0, 1, 2 all, 3 all with the `GPU2D` line, 4 check) and `--gpu2d-wide`.
- `filter2d` (OpenGL/compute): `0` off, `1` on (overrides "Smooth 2D edges"), `2` only the 2x MMPX pass, `3` all passes with identity output, which must match off. See `docs/plan-gpu-2d.md`.
- `filter2drows` (OpenGL and compute, experiment K3), default 1 since 11-11 (`0` redraws the whole map): with filtered 2D, a frame whose keys changed on only some lines redraws only the map rows they can reach. `2` checks: every 30th partial redraw is compared with a full one (`rowchecks` and `rowmismatches` on the `FILTER2D` line). Desktop: `--set Filter2DRows=N` (`--set Filter2DLogging=1` for the line, `--filter2d-mode N` for the `filter2d` modes).

## WideMelon

- `widey` (camera stage 2, `docs/plan-widemelon.md`), default 1, `0` for A/Bs: with 0 the core renders no margin rows above and below the top screen (M = 0), so a zoomed-out camera letterboxes as in stage 1.
- `widepolys` (`docs/plan-widemelon-polylist.md`), default 1 since 11-14, `0` for A/Bs (it's the code before it exactly): with the view wider than 256, the game sees the native view's polygon and vertex RAM counts and DISP3DCNT bit 13, and the scene is kept in a list twice the DS's size, half of it for polygons only the wings show. Latched at the next polygon RAM swap. Savestates add a `GP3W` section only while it's on (old builds skip it; a state saved with a bank over 2048 shows one garbage frame there). Compute builds its programs for 4096 polygons on wide targets with it on (12-bit polygon indices in the work descriptors). A/B it with `widedrops=1`. Desktop: `--set WidePolys=1`; swi-harness: `--wide-check W --wide-polys 1`, `WIDEPOLYS=1` for `wide_check.sh`.

## OpenGL 3D (experiments in `docs/plan-gpu-discovery.md`)

All of these except `gltexprobe` are meant to be exact: A/B them with `hash3d=1`, and `gltimers=1` for the cost.

- `shadowfix` 0: clear the shadow mask over the whole screen for every mask, instead of per line like software. `maskdepth` 0: depth-equal shadow masks and shadows use plain GL_LESS/GL_LEQUAL, without the DS margin. `equaldepth` 0: the same for all other depth-equal polygons.
- `gltrans` (T1), a sum of bits, default 3 (`0` draws as before): `1` skips pass 3's opaque redraw of need-opaque polygons after the clear0 pass, `2` skips need-opaque draws their texture can't pass (CPU scan), `4` (T1c) drops the clear0 pass when the clear alpha is 0 and the GPU has `GL_EXT_shader_framebuffer_fetch`. Without the extension (desktop, maybe Mali) `4` changes nothing. A/B it as `3` against `7`; with `scenestats=1` the `GLTRANS` line's `fetch_frames` counts the frames drawn that way.
- `gledgeskip` (E2), default 1 since 11-12 (`0` draws as before): leaves out the final pass's edge-marking draw, and the whole final pass when fog is off too, in frames where nothing set the edge flag. A/B `gledgeskip=0 glclear=0` against the defaults. Desktop: `--set GLEdgeSkip=0`.
- `gledgemark` (E1), default 1 since 11-15: edge marking (DISP3DCNT bit 5), which GL never drew before E1. The Video setting "Edge marking" (`video_edge_marking`, on by default, hidden for software) sets it at every renderer update; this switch overrides the setting. `0` no edge flags (and Compute's final pass leaves edge marking out too). `1` opaque fragments set the flag when a neighbor one DS pixel away is outside their polygon's outline. `2` every opaque fragment has the flag. Depth-equal (decal) polygons are compared at their own depth: attr G also records whether the opaque draw was moved nearer by the depth-equal margin (`equaldepth`), and the edge pass adds that back. Known gaps: a depth-writing translucent pixel keeps the depth bias bit of the opaque pixel under it; concave polygons (rare on the DS) over-flag along a reflex edge's extended line. Desktop: `--set GLEdgeMark=N` (0-2).
- `gledgefast` (E1 speedups), a sum of bits, default 2 since 11-15 (`0` for A/Bs), exact against `0` on the desktop, the OnePlus 7 Pro and the Pixel 8. `1` the edge pass discards unflagged pixels early and is scissored to the opaque polygons' box; no gain on Adreno or Mali (11-15), so it's off. `2` (with `gledgemark=1`) polygons with up to 4 edges get them as flat varyings instead of texel fetches: OnePlus opaque pass -11%, Pixel 8 neutral at 8x and -9% at 16x. If its programs don't build, it logs once and uses the texture for the renderer's life; `4` makes them fail on purpose to test that. Caveat: GLSL ES doesn't promise the same float results in two programs, so `2` against `0` could differ by a stray pixel on some driver; none seen so far. Desktop: `--set GLEdgeFast=N`.
- `glclear` (D1), a sum of bits, default 3 since 11-12 (`0` draws as before): `1` the plain clear is a `glClearBuffer` per target instead of the full-screen quad, `2` invalidates the attr and depth/stencil targets after the frame. `gltimers=1`'s `clear` part shows the cost. Desktop: `--set GLClearFast=N`.
- `glnodiscard` (R1), a sum of bits, default 3 since 11-13 (`0` draws as before): `1` draws opaque polygons that can't discard a fragment with a program built without `discard`, so the GPU can test depth early (alpha 31, not a shadow or mask, and untextured, decal, or a palette texture without a transparent color 0). `2` adds textures that need a scan (direct, 4x4, palettes with color 0 transparent but unused), cached until texture VRAM under them changes. `4` drops that cache every frame: `7` against `3` must hash the same. Any nonzero value turns step 1 on, so `2` acts as `3`. Z-buffer frames only. With `scenestats=1` the `GLOPAQUE` line counts the polygons, extra draws and program switches. Desktop: `--set GLNoDiscard=0` off, `1` step 1 only.
- `glseams` (floor seams, `docs/plan-gl-floor-seams.md`), a sum of bits, default 0 (`0` draws as before): closes the thin dark cracks GL leaves at T-junctions, as in Pokemon Platinum, Diamond and SoulSilver floors. `1` keeps the hi-res vertex positions' fraction at scales above 1x instead of truncating them to whole target pixels. `2` gives opaque polygons (not lines, translucent, wireframe, depth-equal, shadow or shadow mask polygons) a skirt a target pixel wide, half a DS pixel at 1x, with depth, color and texcoords extrapolated from each polygon's planes, drawn after the opaque pass and only over the clear plane (by stencil), to copy the DS's inclusive edges. With `2`, no pixel a polygon drew changes. The app's "Fix floor seams" setting (Display → Accuracy, OpenGL only) sets `3` or `0`, also mid-game; when the switch is set, it overrides the setting for the whole game. Desktop: `--set GLSeams=N`, or `--at F:GLSeams=N` mid-run.
- `gltexprobe`, a measurement probe for T2 that **renders wrong on purpose**, default 0: bounds how much GPU time a decoded texture cache could save. `1` the texture lookup is one `texelFetch` from the palette texture, alpha 1; `2` a constant with no fetch; `3` is `1` after the old wrap; `4` the wrap plus two dependent fetches like T2's. Never for hash3d or image checks.
- `gltexcache` (T2, `docs/plan-t2-texcache.md`), a sum of bits, default 449 since 11-14 (`0` draws as before and makes no GL objects; `1`, the default from 11-13, is the A/B baseline): textures are decoded once on the CPU into a 16 MB texel heap, kept until texture VRAM under them changes, and the render programs read that instead of decoding VRAM per fragment. `2` decodes every used texture again every frame (check), `4` a tiny budget and heap so both paths mix, `8` no budget and no volatile rule, `16` step 1 (one program with both paths, `17` vs `1`), `32` makes step 2's twin programs fail to test the fallback, `64` step 3 (branchless wrap), `128` step 4 (a color plane for palette textures, re-resolved when their palette changes), `256` (with 128) builds the cache-only programs without the record path. `193` vs `65`, or `129` vs `1`, is exact with animated palettes too. `gltexprobe` wins while it's nonzero. Any change of the value starts the heap over. With `scenestats=1` a `GLTEXCACHE` line once a second: the share the heap served (`cover`, `cover_area`), how (`hit`, `kept`, `decoded`, `redecoded`), why the rest fell back (`range`, `palette`, `volatile`, `budget`, `full`), step 2's twins and extra draws (`s2_*`), step 4's color plane (`color*`, `pal_*`, `resolves`), plus heap use and CPU µs. Field comments are above `GLTexCacheStats` in `melonDS-android-lib/src/GPU3D_GLStats.h`. Desktop: `--set GLTexCache=N`; `--at F:reset`, `--at F:state` and `--at F:GLTexCache=N` reset, reload the `--state` or change a switch before frame F.

## Compositor and output (OpenGL and compute)

- `compclear` (K2a), default 0: the compositor's main draw starts without the output's old contents, so a tiled GPU needn't load every tile first. `1` clears the output to 0 first, `2` invalidates it and clears only the padding rows. Both should leave the output the same. Desktop: `--set CompClear=N`.
- `comp1x` (K2c), default 1 since 11-11 (`0` draws as before): a screen with nothing the scale adds (no 3D, no wings, no hi-res capture lines) is composited at 1x and shown nearest-upscaled. Only with the "None" filter, no deband and no Lua tilt-shift on every surface, and not with GPU 2D lines; with filtered 2D such a screen is drawn at the filter map's scale instead. `1` in a wide view only, where it's pixel-exact; `2` the 256 view too, whose mediump full draw rounds differently on fp16 GPUs (the RTX 5090 too), so the image changes there; `3` checks against a 1x draw every 30 frames (`COMP1X mismatch` lines). With `scenestats` or `gltimers` on, a `COMP1X` line once a second counts the frames at 1x and why the others weren't. Desktop: `--set Comp1x=N` (`--linear` keeps it off).
- `debandfold` (frontend, `docs/plan-deband-outcap.md` part A), default 1 since 11-15 (`0` is the old deband pre-pass): debands inside the Sharp or Linear screen shader instead of a pre-pass over every frame texel, while no Lua tilt-shift runs and the screens draw fewer pixels than the frame has texels. Read by the Kotlin renderer at each game start, so it's not in the perf log's active switches; the `DEBANDFOLD` logcat line says which path each surface uses whenever that changes.
- `outcap` (K4, `docs/plan-k4-output-cap.md`), a sum of bits, default 1 (`0` keeps the output at the internal scale): caps the compositor's output at the scale the screens are shown at. While deband is on, the cap also takes scales that don't divide the internal one (8x gives 6x for a need of 6); with deband off it stays at a whole fraction (8x stays 8x for a 6x screen), since the smaller frame only pays for itself through deband's cost. Bit `2` (`outcap=3`) always takes those scales, bit `4` (`outcap=5`) never does; `2` wins. The `OUTCAP` line gives the ratio and why. `outcapneed=N` overrides the screens' need (1-16). `outcap3d` sets how an output pixel is made from the 3D pixels under it: `0` the exact supersample, `1` and `2` cheaper and inexact, `3` (the default) exact at edges and blends that can clamp, off only by a color average's rounding elsewhere.

## JIT

- `ldmfast` (ARM64 JIT with fast memory), default 1, `0` for A/Bs: multi-register loads (`LDM`, Thumb `POP` and `LDMIA`) read guest memory straight through fastmem like single loads, instead of calling `SlowBlockTransfer9/7` per word. A load that faults is patched to the old slow call. Cycles don't change. Set at game start; changing it later throws the compiled blocks away. User-mode `LDM ^` always takes the slow path. No effect on x64.
- `ldmdirect` (JIT), default 1, `0` for A/Bs: a slow multi-register transfer whose words all fall in one plain region (ITCM, DTCM, main RAM for the ARM9; main RAM or ARM7 WRAM, DS only, for the ARM7) is done straight in host memory instead of a full bus access per word. Same values, invalidation and cycles, so the image should hash the same. Read on every transfer, so it can change any time. Desktop: `--ldmdirect`.
- `jitdispatch` (ARM64 JIT), default 1 since 11-16 (about 1% fewer cycles, frame pacing unchanged), `0` for A/Bs: a block's exit finds the next block and jumps to it in generated code (`Compiler::Gen_DispatchStubs`) instead of returning to the `Execute` loop, falling back to the loop for IRQs, halts, idle loops, the frame's target or a missing block. Same checks in the same order, so emulation should be identical (`tools/jitverify --jitdispatch 0|1`). Read at game start. No effect on x64.

## Frame interpolation

- `halfcam` (OpenGL/compute): frame interpolation for 30 FPS games. `4` is the one to use; `1` camera only, `2` adds characters, `3` adds batch logging, `5` a per-pair trace. When set it replaces the Smooth 30 FPS setting, so `0` forces it off. See `docs/frame-interpolation.md`. The "Debug switches:" line shows the property itself (`-1` when unset); the setting is the `frame_pacing_smooth_30fps` config line.
